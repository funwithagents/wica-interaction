**Status:** Done

Implements the re-designed behavior in `specs/gesture-input.md` ("Frames come from the embodiment", "`StreamFeed`"), `specs/embodiment.md` (`camera(fps=…) -> CameraFeed`), `specs/reachy-embodiment.md` ("Configuration" — the `faces` block; "`RobotCameraFeed`"), `specs/computer-embodiment.md` ("`WebcamSource`" behind a `StreamFeed`), `specs/project.md` (the `vision` extra pulls `vision-modules[hand,opencv]`) and `specs/app.md` (the Vision line's camera rate). Three sibling changes of 2026-09-29 motivate it: `reachy-mini-bridge` retired `get_camera_frame()` for the single-reader camera feed `api.camera` and made face detection opt-in behind a `faces` block (so `motion.tracking: true` now needs `faces.detector`); `vision-modules` made OpenCV an extra and typed its stages against the structural `FrameLike`, so a host's own latest-value slot is a valid upstream. Deliberately leaves out any use of `api.faces` / `api.attention` as an agent input (reachy-embodiment.md open question 5).

## Steps

1. **`gesture_input.py`: the feed seam.** Add `CameraFeed` (a `Protocol`, not extending `FrameSource`; members as in the spec — `latest()` typed `FrameLike | None`). Add `StreamFeed` wrapping `StreamProvider(source, mirror=False)`: `open` → `provider.start()`, `close` → `provider.stop()`, `latest`, `published_count`, `capture_error` → `source.capture_error`. Keep `CameraSource`. Rework `GestureInput`: take `feed: CameraFeed` and `stall_s: float = 3.0` (`>= 0`; validate); `HandStage(feed, …)`; `Pipeline([hands, gestures])`; `start()` does `feed.open()` then `pipeline.start()` then the watcher; `stop()` joins the watcher, `pipeline.stop()`, then `feed.close()`. In `_watch`, meter `feed.published_count`, keep `_last_advance` (monotonic time the count last changed, initialised at `start()`), and in `status()` compute `capture_error = feed.capture_error or (stall line if now - last_advance >= stall_s) or None`. Module docstring: the graph and the two feed rules.
2. **`embodiment.py`:** `camera(*, fps) -> CameraFeed`, docstring per the spec's table row.
3. **`reachy/embodiment.py`:** replace `RobotCameraSource` with `RobotCameraFeed(api)` (pure forwarding, no-op `open`/`close`, `capture_error` `None`, docstring stating why the adapter never calls `api.camera.start()`/`stop()`); `camera()` returns `RobotCameraFeed(self._api)` and ignores `fps`; remove `self._loop`, `_POLL_TIMEOUT_S`, the `threading`/`time` imports if unused. Import `CameraFrame` from `reachy_mini_bridge` for the return annotation.
4. **`computer/embodiment.py`:** `camera()` returns `StreamFeed(WebcamSource(self._config.camera.device, fps=fps))`; adjust docstrings.
5. **Test doubles.** `tests/fakes.py`: `ScriptedCameraFeed` (per Scope) replacing `ScriptedCameraSource`; keep a small scripted `CameraSource` for the `StreamFeed` tests. `tests/reachy/fakes.py`: a `FakeCameraFeed` on `FakeReachyMiniApi.camera` (settable `frame`, `publish()` bumping `frame_id`, `started`/`stopped` counters), drop `get_camera_frame`.
6. **Tests** as listed in Scope; the `GestureInput` tests move from a source to a feed with no behavioural change besides the new health and `StreamFeed` cases.
7. **`app_ui.py`:** the Vision line per Scope; `tests/test_app_ui.py` pins the new wording.
8. **Configs and packaging.** Add the `faces` block to both templates; `pyproject.toml` `vision` extra → `vision-modules[hand,opencv]` and the comment; `uv lock`; `uv sync --dev`.
9. **Docs.** `AGENTS.md` map rows, `README.md` per Scope.
10. **Verification** (below), then flip `gesture-input.md`, `embodiment.md`, `reachy-embodiment.md`, `computer-embodiment.md`, `project.md`, `app.md` from `Updated` to `Implemented` in each file and in `specs/_index.md`; mark this plan `Done` here and in `_index.md`.
