# CI: the end-to-end tier's computer job

**Status:** Done

Implements [specs/ci.md](../specs/ci.md) ("The workflow", "Secrets and protection") for the end-to-end tier's computer scenarios ([specs/e2e.md](../specs/e2e.md)): one Linux job running them against a PulseAudio cable, on every pull request and push to `main`. Before the robot's job, because it validates what both share — the cable, the providers, the secrets, the model downloads — with the fewest moving parts. Leaves out the robot's job and the nightly production run.

## Scope

- `.github/workflows/ci.yml` — the `e2e-computer` job.
- `specs/ci.md` — the job, its devices, its secrets, its place among the checks.
- `plans/_index.md` — this plan's row.

## Steps

1. Write the job: the app's system packages plus PulseAudio and the ALSA pulse plugin; the uv and Hugging Face caches; the sync; the cable (a null sink, a source remapped over its monitor, a second null sink for the app's speaker, each given an ALSA name in `~/.asoundrc`); the scenarios with `-rs`; the evidence uploaded on failure.
2. Push and read the job's log: the device list it prints, the device check, then the scenarios. Fix what Linux reveals.
3. With the two secrets set on the repository, run it until the three scenarios pass; record their times.
4. Mark this plan `Done` and `specs/ci.md` `Implemented`, here and in both indexes.

## Runs

- **First run (2026-11-10):** the cable passed the device check: PortAudio listed `wica_cable`, `wica_mic` and `wica_speaker`. The run then failed on `DEEPGRAM_API_KEY`, whose secret was added a moment after the job started; `WICA_E2E_FAIL_ON_MISSING` turned that into a failure, as designed.
- **Re-run, with both secrets:** the three scenarios passed in 81 s, model downloads included.
- The scenarios' names now print as they run (`-v`), since a first run can sit silent for minutes while the models download.

## Verification

- The other four jobs still green.
