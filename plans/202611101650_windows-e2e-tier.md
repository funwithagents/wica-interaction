# The Windows end-to-end tier, started by hand

**Status:** In progress

Implements [specs/ci.md](../specs/ci.md) ("The Windows end-to-end tier, by hand") and the Windows column of [specs/e2e.md](../specs/e2e.md) ("Platforms"). Delivers a workflow, started by hand, that runs both embodiments' end-to-end scenarios on GitHub's `windows-2025` runner over virtual devices. It leaves out the echo on Windows (the free cable is one cable) and real hardware, which stays a manual check.

## Scope

- `.github/workflows/e2e-windows.yml` — new: the workflow, `workflow_dispatch` only, one runner per embodiment
- `specs/ci.md`, `specs/_index.md` — the Windows tier; `Updated` until this plan is `Done`
- `specs/e2e.md` — the Windows column of "Platforms"; the manual check reduced to real hardware
- `docs/reference/install.md`, `README.md` — what has run on Windows, and when
- `tests-e2e/conftest.py`, `tests-e2e/support.py` — `WICA_E2E_DISCARD_SPEAKER` (the app speaks to no device), the robot's cable named for GStreamer; `specs/e2e.md` `Updated` until Done
- `src/wica_interaction/computer/config.py`, `tests/computer/test_config.py`, `specs/computer-embodiment.md` — a discarded voice with echo cancellation on is a load error
- `pyproject.toml`, `uv.lock` — TEMPORARY: the siblings at their PR branches (tts-engine#33, reachy-mini-bridge#28), back to `main` once they merge

## Steps

1. Bring the workflow up on the `windows-e2e` branch, with a temporary `push` trigger for that branch so each fix runs it alone: the audio service, VB-Cable and Scream installed with `devcon` after trusting their signers, the devices named with their host API, Mesa for the robot's viewer.
2. Fix what each run shows, in the workflow or, when the app or the tier is at fault, in code with a fast test where one can exercise it without devices. A failure inside a sibling is filed in its repository.
3. Once both embodiments pass, drop the temporary trigger, record the measured run (time, passes, skips) in `specs/ci.md`, update the Windows row of `docs/reference/install.md` and the README's status line, and reduce the manual check in `specs/e2e.md` to what virtual devices cannot show.
4. Flip `specs/ci.md` back to `Implemented` and this plan to `Done`.

## Verification

Both embodiments green in a run of the workflow started by hand (`gh workflow run e2e-windows.yml --ref windows-e2e -f embodiments=both`), its link recorded in `specs/ci.md`; then `uv run ruff check .`, `uv run ruff format --check .`, `uv run pyright` and `uv run pytest` (which checks the docs' links and the spec frontmatter) pass locally.
