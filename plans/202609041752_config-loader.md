# Config loader

**Status:** Done

Implements the settled behavior in `specs/configuration.md` — the composed `AppConfig` and the
`load_config(path)` function that splits one JSON file into three sections and delegates each to its
engine's `from_dict`. Delivers only config loading; building live engines (`TTSEngine`, `ASREngine`,
`Wica`) belongs to the tts-output / asr-bridge / app plans.

**Dependencies satisfied.** The three sibling-engine `from_dict` constructors are landed and verified
in this repo's `.venv` (WICA `from_dict(data, *, base_dir=None)`, `TTSEngineConfig.from_dict`,
`ASREngineConfig.from_dict`) — see the "Relies on the engines' `from_dict`" section of the spec. This
plan is ready to implement. (Note: their versions did not bump, so a fresh checkout may need
`uv sync --reinstall-package wica --reinstall-package tts-engine --reinstall-package asr-engine` to
pick up the new methods.)

## Design facts confirmed against the sibling loaders

(Verified in `wica-framework/src/wica/config.py`, `tts-engine/src/tts_engine/config.py`,
`asr-engine/src/asr_engine/config.py`.)

- Imports: `from wica.config import WicaConfig`, `from tts_engine.config import TTSEngineConfig`,
  `from asr_engine.config import ASREngineConfig`.
- Each exposes (verified in the venv): `WicaConfig.from_dict(data, *, base_dir=None)`,
  `TTSEngineConfig.from_dict(engine_block)`, `ASREngineConfig.from_dict(engine_block)`.
- **No `from_dict` reads an env var** — all are structural-only, so `load_config` succeeds with keys
  unset (the "app opens without credentials" story holds; the env read defers to engine build).
- Only WICA resolves a relative path (`agent.system_prompt_file`); passing
  `base_dir=os.path.dirname(path)` locates it against the config file's directory, matching
  `from_json`'s behavior. TTS/ASR configs carry no config-relative paths.
- Valid ASR segmentation modes are `utterance` / `trigger_word` / `timeout`, so the spec's example
  `"timeout"` is accepted.

## Steps

1. **`AppConfig` dataclass** in `config.py`, exactly as the spec's signature:
   ```python
   @dataclass
   class AppConfig:
       wica: WicaConfig
       tts_engine: TTSEngineConfig
       asr_engine: ASREngineConfig
   ```
2. **`load_config(path: str) -> AppConfig`**:
   1. Read the file at `path`; raise a clear `ValueError` (message names the path) if it is missing,
      is not valid JSON, or the parsed value is not a JSON object.
   2. Require all three top-level keys `wica`, `tts`, `asr`; raise a clear `ValueError` naming the
      missing key(s) if any is absent. Require `tts`/`asr` to each contain an `engine` block (the
      shape the composed file documents), raising a clear error otherwise.
   3. Delegate each section to its engine's `from_dict`, in-memory (no temp files):
      - `WicaConfig.from_dict(cfg["wica"], base_dir=os.path.dirname(path))`
      - `TTSEngineConfig.from_dict(cfg["tts"]["engine"])`
      - `ASREngineConfig.from_dict(cfg["asr"]["engine"])`
   4. Return `AppConfig(wica=…, tts_engine=…, asr_engine=…)`.
   - Let each engine's own validation errors propagate (we do not catch/re-wrap field-level errors —
     the spec delegates all field validation to the engines).

## Tests (`tests/test_config.py`)

Functional, no network, no engines built — assert on the returned `AppConfig` and on error paths.
Helper writes a composed JSON dict to `tmp_path/"app.json"` and calls `load_config`.

- **Happy path**: a full composed doc returns an `AppConfig` whose `wica` is a `WicaConfig` with the
  expected provider/model, `tts_engine` is a `TTSEngineConfig` with `module["type"] == "elevenlabs"`,
  and `asr_engine` is an `ASREngineConfig` with `module.type == "deepgram_v2"` and
  `dictation_default_segmentation_mode == "timeout"`.
- **`system_prompt_file` resolves against the config dir**: a composed config in `tmp_path` with a
  relative `system_prompt_file` (`"prompts/assistant.md"`) yields a loaded
  `wica.agent.system_prompt_file` that is the absolute path under `tmp_path` — proving `base_dir` was
  threaded through. Does not require the prompt file to exist (WICA locates, does not read, at load).
  **Compare resolved paths**, not raw string prefixes: WICA's `from_dict` calls `Path.resolve()`,
  which canonicalizes symlinks (on macOS `tmp_path` under `/var/...` comes back as `/private/var/...`),
  so assert against `(tmp_path / "prompts/assistant.md").resolve()`, not `str(...).startswith(tmp_path)`.
- **Missing file / invalid JSON / non-object top level** → clear `ValueError` naming the path.
- **Missing top-level key** (drop `asr`) → error naming the missing key; **missing `engine`** inside
  `tts`/`asr` → clear error.
- **Keys unset succeed**: sections using only `api_key_env` with those vars unset still load without
  raising — pins the "opens without credentials" contract.
- **Engine validation propagates**: an invalid section (e.g. asr
  `dictation_default_segmentation_mode: "nonsense"`) raises the engine's own error.
