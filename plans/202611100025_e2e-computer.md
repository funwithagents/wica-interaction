# The end-to-end tier, part 1: the computer embodiment

**Status:** In progress

Implements [specs/e2e.md](../specs/e2e.md) for the computer embodiment: the tier's shared machinery (the conftest, the support helpers, the `Person`, the configs, the hand photos) and scenarios 1–3 (startup, a spoken turn, hand signs). It replaces `tests-e2e/test_gesture_input_live.py`. Left for later plans: the Reachy Mini embodiment (scenarios 1–4 in the sim), scenarios 5–7, and the tier's CI job.

## What building it revealed first

- **A file as the webcam stalls after one frame.** OpenCV opens an image path as a camera, delivers it once, and then `read()` returns `None` without raising. `WebcamSource` only treated a raised read as a failure, so it neither reopened the device nor reported a `capture_error`: the camera went silent with a clean status, as a real webcam unplugged mid-stream would. A `None` read cannot simply count as a failure, since a webcam warming up returns no frame either (the fast tier pins that it is polled, not reopened). The fix: a device that has delivered a frame since it was opened and then yields none has ended, and is closed and reopened in the same poll. A file then loops at the full poll rate with no error (10 frames in 2 s at 5 fps, measured), and a webcam that went away shows its open failure. The exception path now releases the device too: `OpenCVSource.open()` is a no-op while its capture is held, so the old retry never really reopened.
- **Main's wica predates `wica.testing`.** The tier needs the harness and the checks, so wica moves to `38e3bed`; its checks are now window-based (`run_check`, `CheckContext.scenario_inputs`).
- **Flat files.** `tests-e2e/` is not a package, and the type checker resolves `support` and `person` only from a test file's own directory, so the scenarios are `tests-e2e/test_computer.py` (and later `test_reachy.py`), not subfolders.
- **The framework's `answers_each_input` check cannot see these turns.** It counts a turn from an `input_written` event, which the Probe records only for the tester's own writes. Here the ASR and the gesture input write the World, so the check would pass with zero turns. The tier applies the other three checks, and its own expectations cover answering. An `InputLog` (a World listener on `speech_input` and the hand entries) records what the app's inputs actually delivered, since the timeline holds no input values.

## Scope

- `src/wica_interaction/computer/embodiment.py` — `WebcamSource`: a read with no frame closes the device and reopens it within the same poll.
- `tests/computer/test_embodiment.py` — a source whose read yields nothing is reopened and keeps delivering with no `capture_error`; one that still yields nothing after the reopen records `"camera read failed: no frame"`.
- `specs/computer-embodiment.md` — the `WebcamSource` rule and its testing line.
- `pyproject.toml`, `uv.lock` — `tts-phonon` joins the dev group, and wica moves to `38e3bed`; `specs/project.md` names the extra.
- `tests-e2e/support.py` — `require_env` and a `missing(reason)` that skips, or fails under `WICA_E2E_FAIL_ON_MISSING=1`; `InputLog`.
- `tests-e2e/person.py` — `Person` with `say` (phonon into the person's voice device), `show` and `hide`; `FileCamera`, the computer's camera stage.
- `tests-e2e/conftest.py` — the isolation fixture it already had, the device lookup, the config loader, `person`, `computer_system`.
- `tests-e2e/configs/computer.json` — Haiku, Deepgram Flux, phonon (`Micah`), echo cancellation on, vision on.
- `tests-e2e/fixtures/` — the five hand photos and `no_hand.jpg`, copied from vision-modules, with a README.
- `tests-e2e/test_computer.py` — scenarios 1–3.
- `tests-e2e/test_gesture_input_live.py` — deleted; `specs/gesture-input.md` (frontmatter and testing line), `specs/testing.md`, `AGENTS.md` follow.
- `specs/e2e.md` — the file-as-webcam paragraph (the fix above), the checks paragraph (`answers_each_input` left out, and why), the person's voice (`Harper`), the app's (`Micah`); open questions 1 and 3 resolved.

## Runs so far

On the Mac (2026-11-10), with the laptop's built-in mic standing in for the cable until BlackHole is installed:

- **Scenario 1 (startup)** passes in 24 s: nothing missing, the ASR on its device, the camera file through the hand models.
- **Scenario 3 (hand signs)** passes in 25 s: nothing delivered for 3 s with `no_hand` in view; then `stop`, `stop`, `five`, `one`, `three`, each within about a second of being shown. The agent answered `stop` out loud ("Stopped. I'm not doing anything right now.") and met the counts with `noop`, which the persona allows.
- **Scenario 2 (spoken turn)** has not run: it needs the cable. Played through the laptop's speaker to its mic it is not heard (the mic records only background noise), so it waits for BlackHole.
