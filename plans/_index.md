# Implementation plans

Implementation plans for WICA Interaction (formerly Reachy Mini Interaction WICA) — each plan turns a settled part of a spec (see [specs/_index.md](../specs/_index.md)) into concrete, buildable steps. Plans are ordered by their date-time filename prefix (`YYYYMMDDHHmm_`).

> **Note.** The first four `Done` plans below built the app while it was still a plain vocal assistant (before it was retargeted onto the Reachy Mini robot). The [bridge-integration plan](202609101700_bridge-integration.md) then routed speech through `reachy-mini-bridge` (one `ReachyMiniApi` behind `say` + the robot mic), and the [robot-control plan](202609101715_robot-control.md) added the robot *action* commands (`RobotControl`, registered with the agent). The [merge plan](202609172311_wica-interaction-merge.md) of 2026-09-17 then folded the vocal assistant back in as the `computer` embodiment: the specs those early plans name (`tts-output.md`, `robot-control.md`) were absorbed into [embodiment.md](../specs/embodiment.md), [computer-embodiment.md](../specs/computer-embodiment.md) and [reachy-embodiment.md](../specs/reachy-embodiment.md), and the plan bodies keep their original links as a record. Plans are not rewritten when a file they link to later moves; only this index is kept link-clean.
