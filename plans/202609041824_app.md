# App

**Status:** Done

Implements the settled behavior in `specs/app.md` — the runnable reachy-mini interaction application: the
Gradio UI (Conversation + ASR main surface, World + Prompt debug panels behind a toggle, a typed-text
box), the `main()` wiring that stands up all three engines behind WICA on one app-owned event loop, and
the no-credentials degrade path. Delivers `app.py` plus a committed example config/persona so the app
is runnable, and functional tests for the parts that don't require a browser, mic, or network (the
system build, the typed-text and `on_final_segment` paths driven through the `fake` WICA provider, and
the degrade path). The live browser UI itself is verified manually / e2e, not in `tests/`.

## Deviations during implementation

Refinements found while building; the spec (app.md) remains authoritative and consistent with them:

- **Gradio 6, not 5.** The installed gradio resolved to 6.x, where the messages format is the only
  Chatbot format (no `type=` kwarg). Dependency pinned `gradio>=6`; transcript uses role/content/
  metadata dicts natively.
- **Provider extra added.** `config.example.json` uses provider `anthropic`, so the dependency is
  `wica[anthropic]` (pulls `langchain-anthropic`) — the example runs with just an API key.
- **Independent per-engine degrade** (not "any missing → fully inert"): WICA starts whenever its own
  key is present, so typed text works even with the ASR (and/or TTS) key unset — honoring the spec's
  typed-text rationale ("useful when only the WICA and TTS keys are set"). The ASR bridge starts only
  when the agent is up to consume speech. Empty/whitespace input is ignored in `on_final_segment` so
  both the typed and ASR paths share the guard.
- **`ImportError` also degrades.** A configured provider whose extra isn't installed is surfaced in the
  banner (not just `MissingEnvError`), keeping the "app always opens" invariant honest.

## Decisions locked in for this plan

1. **Three seams in `app.py`, so the wiring is testable without a browser.** Split into:
   - `build_system(config, *, tts_engine=None, asr_engine=None) -> AppSystem` — pure wiring, no Gradio:
     owns the loop, builds/adopts the three engines behind WICA, registers commands + `speech_input`,
     wires `on_final_segment`, collects panel state. The two engine kwargs are **test seams** (inject a
     fake `TTSEngine`/`ASREngine`); production leaves them `None` and builds from config.
   - `build_ui(system) -> gr.Blocks` — the Gradio layout only, reading/writing `system`.
   - `main()` — parse `--config`, `build_system`, `build_ui(...).launch()`.
   This mirrors how the WICA demo keeps wiring behind its public API; here the split is explicit so
   tests drive `build_system` the way `main` does, minus `.launch()`.
2. **App owns the loop and injects it** (`Wica.init(loop=…)`), per spec "One event loop". `Wica` has no
   public loop accessor, so injection is the only way to schedule the ASR/TTS coroutines onto the same
   loop the Agent runs on. `main`/`build_system` create `asyncio.new_event_loop()` and run it in a
   daemon thread; engine coroutines go on via `run_coroutine_threadsafe`.
3. **Per-check no-credentials degrade, app still opens.** Each build that can raise on an unset key —
   `Wica.init` (`MissingEnvError`), `TTSEngine(cfg.tts_engine)` (`tts_engine.config.ConfigError`),
   `ASREngine(cfg.asr_engine)` (`ValueError`) — is wrapped so its failure is captured as a readable
   "set `<ENV_VAR>`" message rather than crashing. `build_system` returns an `AppSystem` carrying any
   such messages; when non-empty, the UI still launches, shows them in a banner, and the live paths stay
   inert (no `wica.start()`, no `asr_bridge.start()`). With all keys present, full wiring + start. This
   is the demo's "opens even with keys unset" behavior, applied per engine.
4. **Typed-text writes `speech_input` directly, bypassing `AsrBridge`** (spec "Typed-text input"): the
   submit handler calls `world.update("speech_input", text)` only while `wica.is_running`; it does not
   synthesize a `SpeechSegment` or touch the bridge. Empty/whitespace submits are ignored.
5. **Panels reuse the demo's instrumentation wholesale.** Conversation is fed by `on_agent_trigger` /
   `on_agent_prompt` / `on_agent_command` pushed onto a thread-safe queue that a `gr.Timer` drains
   (the demo's exact pattern); World/Prompt read live state on a timer. The "Show debug panels" toggle
   is view-only Gradio state (`gr.Checkbox` → `visible=`), changing nothing that runs. This plan does
   **not** re-derive the demo's transcript-rendering details; it ports them, dropping the robot-only
   channels and keeping 🗣️ say / 💭 output sink / 🦾 / 🚫 noop.
6. **`gradio` becomes a real dependency**, and a console entry point `reachy-mini-interaction-wica =
   "reachy_mini_interaction_wica.app:main"` is added — the package *is* the app, so the UI is not an optional
   extra.
7. **Committed example config + persona.** Ship `config.example.json` (the three-section file from
   `specs/configuration.md`) and `prompts/assistant.md` (a plain voice-assistant persona that knows it
   speaks via `say` and can switch to dictation), so `main --config config.example.json` runs against a
   real, documented config. Keys stay referenced by env var, never committed.

## Design facts confirmed against the dependencies

(Verified in the sibling packages already on the path.)

- **`Wica.init(config, *, output_sink=None, output_command=None, coalesce_window=0.2, loop=None)`** —
  `output_command` is a real kwarg (`VoiceOutput.say` goes here); with `loop` injected, `owns_loop` is
  False and `wica.start()` does **not** spawn a loop thread — the app runs `loop.run_forever` itself.
  A missing agent key raises `MissingEnvError` inside `Agent.__init__`, i.e. at `Wica.init`.
- **Engines build from their config section directly**: `TTSEngine(cfg.tts_engine)` and
  `ASREngine(cfg.asr_engine)` (matching `mcp_server_cli.py` / `server.py`). Both resolve their API key
  in their **module constructor**, so a missing key raises at *construction*: TTS raises
  `tts_engine.config.ConfigError`; ASR raises `ValueError` (from `modules/base.py` `_resolve_api_key`).
  `TTSEngine` needs no start/stop; `ASREngine` needs `start()`/`stop()` on the loop.
- **`AsrBridge`** already exposes `start()`, `stop()`, `display_text`, `status()`, `start_dictation()`,
  `stop_dictation()`, and takes `on_final_segment` — the app wires that callback to
  `world.update("speech_input", …)`. **`VoiceOutput.say`** is the bound coroutine to register as
  `output_command`.
- **World Input**: `world.register("speech_input", str, serialize_fn=…, triggers_llm_call=True)`;
  `world.update` is thread-safe but only valid while running (`RuntimeError` otherwise) — hence the
  `is_running` guard on both the typed-text and `on_final_segment` paths.
- **`fake` provider** (INTEGRATING "Testing flows deterministically"): `provider: "fake"` with
  `model_kwargs.script` replays scripted `tool_calls`/`text` per step, `delay_s: 0` removes latency, no
  key/network — the basis for the deterministic wiring tests.

## Steps

1. **Dependencies & entry point.** Add `gradio` to `[project.dependencies]`; add
   `[project.scripts]` `reachy-mini-interaction-wica = "reachy_mini_interaction_wica.app:main"`. `uv sync --dev`.

2. **`speech_input` serialize_fn.** A module-level `fn(value, previous) -> Content` returning a
   `TextPart` — "The person hasn't said anything yet." for `None`, otherwise
   `f'The person said: "{value}".'` (voice-assistant phrasing, not the robot's "closest person").

3. **`AppSystem` dataclass.** Holds `wica` (or `None` when the agent failed to build), `bridge`
   (or `None`), `voice`, `loop`, `missing: list[str]` (the "set `<ENV>`" messages), and the
   panel plumbing (the thread-safe `queue.Queue` of chat events + latest prompts list). A `running`
   property = `wica is not None and bridge is not None and not missing`.

4. **`build_system(config, *, tts_engine=None, asr_engine=None)`.**
   1. Create `loop = asyncio.new_event_loop()`; start `threading.Thread(target=loop.run_forever,
      daemon=True)`.
   2. Build TTS: `engine = tts_engine or TTSEngine(config.tts_engine)`, wrap in `VoiceOutput`; on
      `ConfigError`, append its message to `missing`, leave `voice=None`.
   3. Build ASR: `engine = asr_engine or ASREngine(config.asr_engine)`; construct
      `AsrBridge(engine, on_final_segment=self._on_final)` where `_on_final` does
      `world.update("speech_input", text)` guarded by `wica.is_running`; on `ValueError`, append to
      `missing`, leave `bridge=None`.
   4. Build WICA: `Wica.init(config.wica, output_sink=<sink>, output_command=voice.say if voice else
      None, loop=loop)`; on `MissingEnvError`, append to `missing`, leave `wica=None`. The output sink
      pushes 💭 text onto the chat queue.
   5. If `wica` built: `wica.register_command(bridge.start_dictation)` /
      `register_command(bridge.stop_dictation)` (when `bridge`); subscribe the three panel Events to
      queue-pushers + prompt-collector; `world.register("speech_input", …, triggers_llm_call=True)`.
   6. Return the `AppSystem` (do **not** start here — `main` starts, so tests can inspect a built-but-
      stopped system).

5. **`main()`.** `argparse` `--config` (default `config.example.json`); `logging.basicConfig` +
   `wica` at INFO (demo pattern); `system = build_system(load_config(path))`; if `system.running`,
   `system.wica.start()` then `run_coroutine_threadsafe(system.bridge.start(), system.loop).result()`;
   `build_ui(system).launch()`. Wrap `load_config`'s own `ValueError` (bad file) into a UI banner too,
   so a malformed config still opens with an explanation rather than a traceback.

6. **`build_ui(system)`.** Port the demo's four-panel layout, minus robot bits:
   - **Conversation** (`gr.Chatbot`-style) drained from the queue by a `gr.Timer(0.2)`.
   - **ASR panel**: live `bridge.display_text` + `bridge.status()` on a timer; **Stop dictation**
     button (`enabled` while `status()["dictating"]`) → `run_coroutine_threadsafe(bridge.stop_dictation(),
     loop)`; **typed-text** `gr.Textbox` whose submit calls the guarded
     `world.update("speech_input", text)` (ignore empty). When `bridge is None`, the live/dictation
     controls are replaced by the degrade note; the typed-text box stays usable.
   - **Debug toggle** `gr.Checkbox("Show debug panels", value=False)` controlling `visible=` of the
     **World** table and **Prompt** dropdown+textbox (both fed on timers as in the demo).
   - A top **banner** rendering `system.missing` (and any config-load error) when non-empty.

7. **Example config + persona.** Write `config.example.json` (the `specs/configuration.md` three-
   section shape, provider `anthropic`, env-referenced keys) and `prompts/assistant.md` (plain helpful
   voice assistant: replies via `say`, keeps turns short, offers dictation when asked to take a longer
   passage). `system_prompt_file` is `prompts/assistant.md`, resolved relative to the config file.

8. **Spec/index bookkeeping.** Set `specs/app.md` frontmatter `tests: [tests/test_app.py]`; on green,
   flip `app.md` `Stable → Implemented` and mirror in `specs/_index.md`; mark this plan `Done` here and
   in `plans/_index.md`.

## Tests (`tests/test_app.py`)

Functional, deterministic, no browser/mic/network. Use a `fake`-provider `AppConfig` built with
`WicaConfig.from_dict({...})` (script with a `say` call), and inject fakes for the engines via the
`tts_engine=`/`asr_engine=` seams so no ASR/TTS key or audio device is needed:

- A `FakeTTSEngine` recording each `say(text)` (as in `test_tts_output.py`).
- A `FakeASREngine` exposing the surface `AsrBridge`/`build_system` touch (`on_speech_segment`
  attribute, `status()`, `dictating`, `segmentation_mode`, `start`/`stop`/`start_dictation`/
  `stop_dictation`) — construction must not need a key.

Tests (drive the public `build_system` the way `main` does, then start the returned system):

- **Typed-text drives the agent and reaches TTS.** Build with all fakes + `fake` provider (script:
  one `say("hello there")`), `wica.start()`, run the typed-text submit path with `"hi"`; poll briefly
  until the `FakeTTSEngine` records `"hello there"` — proving typed text → `speech_input` → agent →
  `say` output Command → engine. Assert the fake recorded exactly that utterance; assert empty/`"  "`
  submits record nothing (guard).
- **`on_final_segment` reaches the agent identically.** Instead of typed text, invoke the bridge's
  `on_final_segment` (i.e. simulate a closed segment) and assert the same script fires the `say` — the
  ASR path and typed path share one World update.
- **Degrade path names the missing env var and does not raise.** Build from a config whose TTS section
  references an unset `api_key_env` (real `TTSEngine`, no fake) — assert `build_system` returns rather
  than raising, `system.running is False`, and `system.missing` contains the env-var name. Repeat for
  an unset WICA agent key (`MissingEnvError` → captured). This pins the "opens even with keys unset"
  contract at the build seam without launching Gradio.

(No test asserts on Gradio widget objects or renders the UI — that surface is manual/e2e, consistent
with `specs/testing.md`.)
