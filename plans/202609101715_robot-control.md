# Robot control — the agent's Reachy Mini action commands

**Status:** Todo

Implements [robot-control.md](../specs/robot-control.md): the `RobotControl` WICA commands wrapping the
bridge's action verbs (`play_emotion` / `list_emotions`, `start_head_tracking` / `stop_head_tracking`,
`get_motors_state` / `set_motors_state`), registered with the agent. Depends on the
[bridge-integration plan](202609101700_bridge-integration.md) (the shared `ReachyMiniApi` and its
loop lifecycle) landing first.

> **Gate.** [robot-control.md](../specs/robot-control.md) is still `Draft` (it carries load-bearing
> open questions — notably whether motor management is agent-facing, and prompt-seeding vs. live
> `list_emotions`). Settle it to `Stable` before executing this plan; the steps below assume the v1
> command set the spec describes.

## Scope

- `src/reachy_mini_interaction_wica/robot_control.py` — replace the stub with `RobotControl`: hold the shared `ReachyMiniApi`, expose the six commands as non-raising bound async methods returning readable strings.
- `src/reachy_mini_interaction_wica/app.py` — build `RobotControl(api)` (the same api as `VoiceOutput`) and `wica.register_command(...)` each command; optionally seed emotion names into the prompt (per the spec's open question).
- `tests/test_robot_control.py` — functional tests against the bridge's `fake` backend (add the path to the spec's `tests:` frontmatter).
- `specs/robot-control.md` — flip `Draft` → `Stable` (before) then `Stable` → `Implemented` (after), keeping [specs/_index.md](../specs/_index.md) in sync.

## Steps

1. **Settle the spec.** Resolve robot-control.md's open questions to deferrals; promote to `Stable`.
2. **Implement `RobotControl`.** Wrap each verb: catch `MotorsNotEnabledError` → a "motors are off, enable first" message; catch `ValueError`/`BridgeError` → `"<verb> failed: <msg>"`; success → `"OK"` / the state / the emotion list. `list_emotions` returns the names; `play_emotion`/`start_head_tracking` note the motor precondition in their docstrings (what the model sees).
3. **Register.** In `app.py`, build `RobotControl(api)` and register all six commands alongside `say` and the dictation commands; decide prompt-seeding of emotion names.
4. **Test.** Drive against the `fake` backend: emotion list/play (known + unknown), motor precondition enforced when disabled and satisfied once enabled, `get_motors_state` reflects `set_motors_state`.
5. **Docs/status.** Add `tests/test_robot_control.py` to the spec frontmatter; flip robot-control.md to `Implemented`; update the persona prompt if needed; mark this plan `Done`.

## Verification

- `tests/test_robot_control.py` covers the behaviors above (asserting behavior, not exact strings), all against the deterministic `fake` backend — no hardware, no network.
- `uv run ruff check .`, `uv run pyright`, `uv run pytest` all pass. A live `sim`/real-robot check belongs in `tests-e2e/` and is not required to mark this `Done`.
